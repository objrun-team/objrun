Pin official revision `6c6fe63a8c87f15e8fa05f3bcb549a3d44190b5d`, under Realistic conditions. Exclude the manual autonomous-de task; retain 45 single tasks and one four-stage task, totaling 49 scientific problems. The four arms are single-shot, real ObjRun, independent sampling, and binary feedback. Costs are not matched, and no per-task dollar cap applies.

Implementation: `examples/benchmark/theophyseval/experiments/`. This run uses workspace directory `tmp/theophyseval-20261016-v3/`; the controller runs on the Windows host, while scientific computation uses Harbor 0.22.0 DockerEnvironment with official pinned images. Python dependencies are installed separately at `tmp/theophyseval-runtime/venv/`. Grading uses original functions from official grader_runtime in a trusted host Python process. The grader executes no candidate code and mounts neither tests nor reference answers into solver containers.

`prepare.py` pins data, separates public/private materials, and reuses the audited SciCode engine snapshot. Each native-engine solving unit uses c5, 600 seconds, 4 branches, and 12 units. Each of the other three arms permits at most 12 tool-solving model calls and 600 seconds per stage; one round is a complete task workflow. Independent and binary arms allow at most 5 rounds, stopping when the entire task passes. Independent rounds use fresh containers and context; binary retains this task’s context and environment but receives only whole-task passed/failed as external correctness feedback. All four-stage arms inherit only handoff actually computed in the current round; independent retries restart at stage one.

Shared tools are compute and snapshot. compute runs commands only inside the current solver container. snapshot pauses it, freezes all of /output, creates an immutable candidate identity with file hashes, then resumes the container. ObjRun submit and verify accept only candidates from that session; final grading binds to the actual finalCandidate. Format failures may explain public file/syntax requirements; correctness receipts reveal no numerical error, tolerance, or reference answer.

Grader self-tests cover positive, invalid, and missing answers for all 49 problems; clearly wrong numerical answers for 45; tolerance boundaries; alternative answers; and shared-scale normalization. Container controls cover internal timeouts and nested-child termination, unauthorized-request rejection, UID, test/key isolation, candidate freezing, independent environment reset, cross-session candidate rejection, and the four-stage template. Engine controls use synthetic model responses while actually executing compute, snapshot, verify, and submit, without paid model calls.

The pilot was preselected as axion-dielectric-conversion, sllod-thermostat, dispersion-pi-series, and all-electron-to-crystal: 16 task workflows across four arms, yielding 28 scientific-problem terminal states. The pilot is engineering development data; formal summaries including these tasks must disclose that and separately report tasks unused for development. Only after grading, container, native-engine controls, and item-level pilot audits pass does supervise.py write pilot-acceptance.json and start the authorized full four-arm run of 46 tasks / 49 problems. A wrong scientific answer is not an infrastructure failure.

Model: OpenRouter deepseek/deepseek-v4.1-flash / DigitalOcean / high / temperature=0 / 16384 tokens. Preserve the actual canonical model, receipts, costs, and unknown costs. Interface calls have at most 3 bounded attempts; do not automatically increase account limits or switch models. Existing launch records prohibit duplicate startup. Unfinished tasks require separate explicit recovery, not deleting locks and regenerating.

Outputs include each round’s context, model requests and raw responses, generation IDs, cost receipts, tool records, candidate manifests, stage-level grading, ObjRun SQLite/task trees, source pins, and audit reports. Data and engine provenance digests are in data/source-pins.json and data/engine-origin.json. The formal score denominator is fixed at 49; never count both four-stage problems and their parent aggregate criterion.
