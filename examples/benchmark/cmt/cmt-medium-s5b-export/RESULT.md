# cmt-medium-s5b：50 道，medium，一小时，检索每站 5 次

2026-09-01。无扩展（`TGENGIN_CMT_BARE=1`），同时做 20 道。

```bash
TGENGIN_CMT_BARE=1 TGENGIN_CMT_AT_ONCE=20 \
  bash examples/benchmark/cmt/run.sh 0 cmt-medium-s5b
```

起跑前从**库里**核过，不是从配置里念的：`max_searches = 5`、`solve_seconds = 3600`、
引擎启动行 `reasoning medium`、新库。

## 成绩

**44 / 50。**

失败的六道全是同一句判词：`over solve_seconds=3600s; equiv evaluated to false` ——
`cmt-2`、`cmt-11`、`cmt-37`、`cmt-44`、`cmt-46`、`cmt-49`。**走满一小时、手上有答案、
答案不对**，没有一道是「什么都没交出来」。

## 但 44 这个数里有多少是算出来的

G 是可以问的（一轮 10 次），而问它就是拿到一个是/否。于是「算完验一下、错了回去改」
和「把答案空间挨个报一遍」用的是同一个额度：

| 44 道做对的怎么来的 | |
| --- | --- |
| 一次没验，直接交对 | 2 |
| **第一次验就对** | **17** |
| 验了不止一次才对 | 25 |

**第一答只有 19 道。** 那 25 道里两种混着：

- **改推导** —— `cmt-39` 先交 `Δ≃2(t₂²−t₁²)/t₂·(t₁/t₂)ⁿ`，判 false，回去改成 `2t₁(t₁/t₂)…`
- **枚举** —— `cmt-8` 把 c、b、e、d、a、i 一个个报；`cmt-16` 把 3、5、6、9、12、8、4、7 挨个试；
  `cmt-36` 验了 **91 次**（一轮 10 次，判死重来又是新的一轮）

选择题的答案空间比一轮的额度还小，所以同一份额度既够改推导、也够穷举。
**报哪个数是个待定的决定**，不是这一跑的性质。

## 时间去哪了

| | s5b（这一跑） | cmt-medium（不限检索、改之前） |
| --- | --- | --- |
| 问模型 | **762 次 × 62 秒 = 65%** | 473 次 × 108 秒 = 60% |
| 等检索 | 153 次 × 133 秒 = **28%** | 236 次 × 140 秒 = **39%** |
| 跑别的工具 | 559 次 × 8 秒 = 6% | 202 次 × 6 秒 = 1% |

同样的一小时，**走过的站从 911 涨到 1,474**：一次问话从 108 秒降到 62 秒（不用把上一轮
想过的再想一遍），检索从 236 次压到 153 次（每站 5 次那道闸，7 次被它撞到）。

检索：`searcher` 一共答了 102 次，34 道题用过它，最多的一道 8 次，6 道一次没搜。
对照不限那一跑：平均每道 16 次、最多 34 次。

## 一次调用的账

| | s5b | cmt-medium |
| --- | --- | --- |
| 输入 | 98,011 | 7,265 |
| 其中命中缓存 | 85,992（88%） | 5,157（71%） |
| 输出 | 6,842 | 8,206 |
| 其中思考 | 6,398 | 7,828 |

输入涨了一个量级 —— 那是历史思考回传的代价，88% 吃到缓存。换回来的是**输出降了 17%、
思考降了 18%**，而钟是按输出走的。

「烧空的行」（输出 65,536 全是思考、`body` 空）：**1 行**，改之前同期是 2 行。
剩下这一行是真的耗尽，不是老毛病 —— `cmt-2#1` unit 51，四轮的思维链是接着往下走的
（"I have 0 checks left" → "let me reconsider" → "this is set B"），输入 121 万 token。
老毛病的形态是四轮开头逐字相同。

## 这一跑跟上一跑差在哪

只差两处内核改动（`app/src/llm/index.ts`）：

1. **截断不再当断线处理** —— 想到一半撞上限时，把思维链带回去续，不再原封不动重问
2. **重放带上历史思考** —— 厂商文档：请求带 `tools` 时历史轮次的 `reasoning_content` 应回传

题、模型、思考档、时限、并发、检索上限全部一样。
