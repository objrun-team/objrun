## Rationale

**Why split the nodes this way?** The official harness itself has two stages: run test.sh, then read reward.txt. A missing file from a crash, timeout, or OOM and a file containing 0 both score 0 on the leaderboard, but convey different information to the solver: the former is usually an environment problem. Like deepswe's `applies → resolved`, this introduces no new criterion.

**Why is cand container state rather than a file list?** Statements fix the output paths, and verifiers directly call things like `open('/root/xxx')`. Asking the solver for a list to copy would make us decide which files the official criterion may inspect. That could miss forbidden files under `/root`, or a Lean project that must compile as a whole. Snapshot the complete container and let the official criterion inspect whatever it needs.

**How are fractional rewards handled?** The paper's pass criterion is binary, reward=1, while the leaderboard's `mean(reward)` gives partial credit on seven tasks. Our G is boolean, so it uses `reward == 1.0`: consistent with the paper, stricter than the leaderboard on those seven tasks. Notes retain the reward value, allowing leaderboard-style scores to be calculated afterward.

**Skills are this benchmark's independent variable.** The paper compares the same model with and without skills. The grader's `--skills with|none` selects separate experimental runs without changing G's shape.

## Not yet verified (code has not run on this machine)

1. All of stand.py remains unrun: Sherlock has no docker, and Python is prohibited on the login node.
2. PyYAML parses task.md YAML frontmatter. We assume `yaml.safe_load` accepts all 87 files with `schema_version: '1.3'`; only three were inspected.
3. Whether a docker commit snapshot can directly run `docker create … bash /verifier/test.sh`: images must contain bash. The 53 ubuntu:24.04 and 29 Debian-based `python:*-slim` tasks do; suricata/oss-fuzz are unchecked.
4. Official `cleanup_conftests` implementation is unseen; BenchFlow is a separate repository that was not cloned. We use `find / <workdir> /root -maxdepth 1 -name conftest.py -delete`, deleting only top-level files while preserving the task repository's own conftest. Scope may differ from the official implementation. Agent-created cwd `pytest.ini`/`pyproject.toml` files can still change rootdir.
5. The verifier container bind-mounts `/logs` and writes as root, preventing deletion by an ordinary host user. We copied deepswe's container-assisted `wipe()` but have not tested it with these images.
6. A regex takes the last Dockerfile `WORKDIR` as the agent cwd (66 under `/root`, 15 under `/app`, etc.). A variable form, `WORKDIR ${WORKSPACE}`, is captured literally; that task requires a manual correction.
7. `/place` forwarding (`Runtime` class and `/rt` binary) is copied from deepswe. We assume `dist/tgengin-runtime-linux-x64` runs in these images; glibc compatibility is uncertain for the two ubuntu:20.04 bugswarm tasks.
8. Snapshot cache keys use the docker diff path set with a 90 s TTL, so the two nodes of one hand-in share a grading run. Changing content without changing that path set and verifying again within 90 s returns the old judgment. Accepted by design, but not tested.
9. Whether the official oracle assumes no skills injection: oracle mode at `run_benchflow_integration.py:392` omits injection, and self-tests follow that convention.
10. Total disk space and build time for all 87 images have not been measured.
