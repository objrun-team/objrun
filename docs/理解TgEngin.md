# 理解 TgEngin：它是什么、为什么这样设计、放在哪里看

写给刚接触 TgEngin 的研究者。目标是让你在读代码之前先有一张地图，读代码时知道每一处为什么长成那样。文中所有代码路径相对仓库根 `TgEngin/`。基于 2026-09-30 的代码（commit b45758c 之后的工作树）和 `docs/` 里的设计记录。

---

## 0. 一句话

**TgEngin 是一台只让人写「成功判据」的研究操作系统；判据叫 G，其余一切（模型、搜索、执行地点、工具、规则、技能）都是可替换的数据。**

论文（`latex/`）目前把它写成「验证器通道的测量协议」。那只是它的一个切面。先读这份文档，再读论文，你会知道论文里哪些是主张、哪些只是证据。

---

## 1. G 的本质

形式上，G 是任务的一个全函数 `G_τ : cand_τ → {0,1}`，由持有标准答案 y* 的外部评判器计算，密封、按预算查询、按信息级别回话（`objective/spec.ts`、论文 Def.1）。

从四个角度看它是什么：

| 角度 | G 是 | 传统对应 | 代码体现 |
|---|---|---|---|
| 认识论 | 可证伪程序；一个问题只有存在「这算不算答案」的判定程序时才算提清楚 | Popper、预注册 | 值域封闭为 bool，违约归 0，没有第三态 |
| 计算 | 验证器；验证比寻找便宜的那份不对称就是任务的难度 | NP 的验证/搜索 | Δ = solve@N − pass@1 测的就是这份不对称 |
| 信息 | 配给的现实通道；G 是机器唯一接触世界的地方，ĝ（自评）是它的想象 | 实验、Lean 类型检查、测试 | c、K、level 是带宽，note 是人类知识进入搜索的缝 |
| 权力 | 优化对象碰不到的宪法；人保留的唯一权力是定义「做成」 | 内核/用户态、奖励不可改写 | 封存区、`source=agent` 不许带 G |

合起来：**G 是「实验」这一角色被抽象成的数据记录**。它可以是 Lean、隐藏测试、sympy 等价、化学解析器，也可以是一台仪器或一次湿实验（G 的节点可以是 `http://` 句柄）。

两个推论：
- **知识住在 note 里。** level 0 只说「不对」，level 3 说「哪里不对」。两者之差就是人类领域知识的可测量价值。ChemIQ 的 G 特意写「不出差多少」，因为带宽一旦超过 log₂m，G 就从验证器退化成答案泄漏口。
- **好的 G 认证多、泄漏少。** Lean 是极限：命题公开、泄漏为零。答案匹配类 G 最弱，所以才需要封存。长期方向是把每个域的 G 往 Lean 那一端推，从「藏答案」走向「公开规格」（`readable=true`）。

G 不是什么：不是奖励（标量，用于优化；G 是判定，用于终止），不是评审（可被说服；G 只能被满足），不是「更好」的度量（G 只答「是否完成」；开放式改进要在 G 外加门槛并重新发布）。

## 2. 一条原则推出所有设计

若 G 是边界，系统只需满足三条要求：

1. **G 之外的一切都碰不到 G**
2. **G 之外的一切都可以替换**
3. **G 说过的每句话都留有记录**（分数只能从 G 的判决算出）

| 设计 | 落在哪条 | 目的 | 位置 |
|---|---|---|---|
| 内核里不出现任何具体的模式/工具/规则/智能体名 | 可替换 | 除 G 外没有任何东西有特权 | `engine/loop.ts` 头注释 |
| 表结构由声明生成；子表 `task_{mode}`、`agent_{name}_ctx/_msg` 从数据里长出来 | 可替换 | 运行时声明新机制、新智能体，不停机、不改代码 | `install/index.ts`、`install/tables.json` |
| handle 表统一 `fn:` 与 `http://`；两层核对 | 可替换 | 执行单元和 G 节点都可以是外部服务 | `engine/registry.ts`、`docs/tables.md` |
| place 层：local / WSL / 容器 / ssh / 浏览器标签页 | 可替换 | 同一引擎落在任意执行环境 | `place/`、`examples/place` |
| 搜索策略是 `infer` 句柄 | 可替换 | 换搜索 = 换一个函数，内核不动 | `tree/dfs.ts` |
| trigger 表统管工具、skill、规则 | 可替换 | **可演化层**：自我改进以插行的形式发生 | `engine/trigger.ts` |
| G 定义存单独库 `db.sealed`，主库全开放 | 碰不到 | 靠够不着，不靠规定 | `objective/store.ts` |
| `source=agent` 的任务不能带 G；闸只在唯一入口 | 碰不到 | 智能体不能自定成功标准 | `tasks/publish.ts` |
| `verify` 从库里查任务号，不收调用方参数 | 碰不到 | 不能拿别人的 G 问自己 | `objective/tool.ts` |
| 值域封闭 bool / bool[n]；违约归 0；发布时十条静态检查 | 碰不到 | G 是全函数且可判定 | `objective/spec.ts` |
| ĝ 往下走，G 只在自称完成时复核 | 碰不到 | 内部完全自主，但不许自己说了算 | `tree/dfs.ts` 头注释 |
| c、K、T 预算 + 枚举零模型 | 碰不到 | 通道带宽受配给 | `objective/tool.ts`、论文 Prop. enum |
| 判决以 `verify` 工具结果的形状投进上下文 | 有记录 | 通道是一等公民 | `msg/deliver.ts` |
| 库即快照；判死、状态、分数都是算出来的 | 有记录 | 没有人能写分数 | `engine/loop.ts`、`docs/loop.md` |
| `kind` 由「谁放的」推出，不由调用方填 | 有记录 | 人、规则、工具、模型的贡献可归属且不可伪造 | `msg/deliver.ts` |
| 压缩落库（l1–l4），当前节点永远原文 | 有记录 | 上下文可复现 | `msg/press.ts` |
| `/check`、`/trigger/check`、`/trigger/explain` 开机自动跑 | 有记录 | 静默失效会污染测量 | `trigger/check.ts` |

`docs/迁移.md` 里列的「定理，一条都不许破」是这三条的工程版本，读代码前先看。

## 3. 一道题怎么跑（对照 `docs/loop.md`）

```
发布：人写 d + G → 静态检查 → G 封存 → 首站写库 → 计时 T
attempt：ask（看祖先链全部消息 + 结构化视图）→ act（工具）→ 途中可 verify(x)，本轮 ≤ c 次
交卷：调 submit / 说出非空话 / 工作预算用完
     H1 没交 → 0；H2 与本任务已验过的原文一字不差 → 复用判决；H3 跑 G
判 1 → reached；判 0 → dead
dead 后：已死节点 < K 且 t < T → 开新节点，上下文继承全部历史，c 和 U 重置，产物不继承
t = T → 关掉，最后一份候选再判一次为终
```

N = (K+1)(c+1)+1 是一道题最多的评判器调用数。分数曲线 S(n) 从 checks 表按题累计得出。

## 4. 放在文献里的位置

### 4.1 层次

| 层 | 东西 | 回答的问题 |
|---|---|---|
| 应用 | AI Scientist、autoresearch、benchmark 跑分 | 用它做什么 |
| **运行时 / 协议** | **TgEngin**、LangGraph、Temporal | 谁持有判据、谁可以问、问几次、记什么 |
| 判据 G | Lean、隐藏测试、sympy、解析器、实验 | 什么算做成 |
| 求解器 | 模型、采样、RLVR 策略 | 怎么生成候选 |
| 定律 | Monkeys、Snell | 求解器对着 G 能走多远 |

Lean 是一个 G（`examples/benchmark/minif2f/G.md` 就把 Lean 挂成节点），Monkeys 是对着 G 的一条定律，TgEngin 是挂载任意 G 的运行时。三者不在同一层。

### 4.2 G 放在哪里 × G 由谁写

| | 事后 | 循环里（推理时） | 训练里 |
|---|---|---|---|
| 通用形式化（Lean） | Prover 采样 | 交互式证明 | AlphaProof |
| 按域人写 | **Monkeys**、SWE-bench | Reflexion、CodeARC、**TgEngin** | RLVR |
| 模型自评 | 多数投票 | AI Scientist | self-rewarding |
| 系统改自己 | | | DGM、STOP |

TgEngin 与 Reflexion、CodeARC 同格，差别在：G 是任意 DAG；查询有预算和信息级别；有一个把 G 密封起来的运行时。可以理解为**不更新权重的 RLVR**。

### 4.3 与四类工作的根本区别：V 的信息写到哪里

| | Monkeys | TgEngin | RSI（STOP/DGM/AlphaEvolve） |
|---|---|---|---|
| V 的信息写到哪 | 不写，只用来挑 | 上下文 | 系统本身（代码/harness/权重） |
| 活多久 | 0 | 一道题 | 永久 |
| 对 V 成本的假设 | 便宜、可并行 | **贵，省调用次数** | 便宜、要评估成千上万变体 |

- **Monkeys 的 pass@k 是当前生成器的能力包络。** TgEngin 的 H1 问的是：同样的 V 调用次数下，串行条件化能否超过包络。这是 RSI 的必要条件探针：同一道题、信息就在上下文里都不行的话，跨题固化更不行。
- **RSI 缺的前提是可靠且便宜的验证（MetaRSI 的「定律」）。** TgEngin 把它做成可移植、可编写、密封的产物。架构上三层：G（人写、不变量）→ 引擎（固定）→ skill/rule（可演化）。RSI 的安全边界在这里有结构性答案：边界就是 G，而 G 不在被优化的对象里。
- **AI Scientist 只有 ĝ 没有 G**，模型给自己打分，正是 TgEngin 入口闸禁止的自提权。
- **autoresearch 做对了最关键的一件事**（评估只读），但 G 是一个域的一个标量，靠 program.md 一句约定守着，查询无限次。TgEngin 是它在任意域上的协议化版本。`docs/loop.md` 末尾有逐条对照。

### 4.4 三个零模型（TgEngin 的方法论可推广到 RSI）

| 零模型 | 内容 | 谁需要 | 手上的证据 |
|---|---|---|---|
| 枚举 | 答案空间 ≤ 预算时，解出只说明预算够 | 所有 verifier 在循环里的评测 | CMT 26 次救回里 15 次是枚举 |
| 选择偏差 | RSI 外循环是对系统变体做 best-of-k，噪声下必有账面提升 | DGM、AlphaEvolve、ADAS | ChemBench 同配置重跑 167 vs 175（约 10% 噪声） |
| 答案回流 | 同一批题上改进又测试 = 记住答案 | 所有不做留出的 RSI | — |

## 5. 为什么效果好

**Δ ≈ 覆盖（模型）× 不对称（任务）× 带宽（G）− 泄漏（枚举）**

| 因子 | 机制 | 证据（V4-Flash-0731，2026-09-26 六榜 U/F） |
|---|---|---|
| 覆盖 | 当前模型 pass@k ≫ pass@1，答案在分布里只是挑不出来；G 让模型顺着判决剪枝 | CMT 26→86，miniF2F 44→77 |
| 不对称 | 验证比寻找便宜多少，G 就买回多少 | Δ 随答案空间递增：AIME 撞天花板，GPQA +3.5，CMT +60 |
| 带宽 | note 把人的诊断放在杠杆最长处：百行 G 影响该域每题每次尝试 | DeepSWE：新行为测试 >90% 通过时下一候选 33% 被接受，≤50% 时 2% |
| 不许自证完成 | 智能体最常见失败是过早宣布完成；拿走这项权力，第一次失败自动变成带真实理由的第二次尝试 | CMT 11 次救回是修改后的推导 |
| 泄漏（负项） | N ≥ m 时 G 自己把题解了，系统自己标出并扣除 | CMT 15/26；ChemIQ 226/816 可枚举 |

工程层面另有两条：接入一个域只需约百行 G（八个域合计 757 行，`examples/benchmark/*/G.md`），迭代单位小；分数从 trace 算出、零模型扣除、pass@1 成对报告，数字站得住。

**诚实的一句：Δ 是时代属性。** 它大是因为当前模型覆盖高、精度低。pass@1 逼近 pass@k 时 Δ 缩小（AIME 已如此）。G 不能创造候选。TgEngin 的长期价值不在 Δ 的大小，而在三条要求本身。

## 6. 数据库设计为什么值得单独看

「系统等于数据库」：内核无状态，树、上下文、规则、工具、判决、成本全是行，唯一的墙是 G 所在的另一个库文件。各构件业界有先例（event sourcing、Temporal、Smalltalk image），组合起来用在智能体上是新的。

对自动科研的意义：
- 实验记录本就是机器本身；结果不可能伪造、不可能幻觉。
- 自我改进是往表里插行（skill + trigger），可 diff、可回滚、可留出 A/B，碰不到 G。相比 DGM 改自己的代码，这是最安全的 RSI 形态。
- `kind` 不可伪造，人和机器的贡献可归属。
- 复制一个 `h2h.sqlite` 就复制了一次实验（`runs/*/` 每跑一个库）。

## 7. 已知边界与待办（不要回避）

| 类别 | 内容 |
|---|---|
| 形式 | G 是布尔值，覆盖可验证科学；开放式「做得更好」没有原生表达。「问什么」仍在系统之外 |
| 封装 | 是隔离不是对抗强度。规则在四刻跑但**不拦**，没有 `pre_call`（见 `paper2/README.md`）。公开题库能联网就能拿到答案（ChemIQ G.md 自述） |
| **安全（高优先级，待核）** | `config.yaml` 默认 token 为空、`allowWrite: true`、引擎在 127.0.0.1:7801。若解题器的 bash/python 与引擎同机（`place=local` 的榜），理论上可 `curl /api/exec` 改 checks 表。**尚未检查各 run 的 tools 表是否出现过 7801 或 `/api/`**。跑 bench 应关写、配 token |
| 扩展性 | 内核每 tick 全表扫 `done=0`；SQLite 单写者；库在 Lustre 上。几十题并发没问题，上千需要分片 |
| 实验缺口 | P 臂（pass@n）只设 n∈{4,8}，而 N=64–100，要采到 n≥N；L 臂（level 0–3）是证明「G 内容有价值」的关键，未跑；只有一个模型；G 编写成本未量化 |
| 论文 | 正文仍写「没测 pass@1」，与 9-26 的六榜 U 臂数据不一致；Fig.1 六组旧数来自另一系统已作废（见 `01-数据总表.md`） |

## 8. 读代码的顺序

1. `docs/迁移.md` 的「定理」一节，`docs/loop.md` 全文
2. `engine/loop.ts` 头注释 → `tree/dfs.ts` 头注释 → `objective/{spec,store,tool}.ts`
3. `tasks/publish.ts`（唯一入口和闸）、`declare/index.ts`（整份收整份验）
4. `docs/tables.md`：trigger、rule、tool、skill 四节
5. 任选一份 `examples/benchmark/*/G.md`（推荐 chemiq：字段最全，含 m 表和已知坑）
6. `runs/bench-arm.sh`：一跑怎么起、库怎么隔离、U 臂怎么事后判分
7. 论文 `latex/sections/03-protocol.tex`、`06-preregistration.tex`

写一份新域的 G 时，照 chemiq/G.md 的字段表：来源、cand、structure、h_r、boundary、budget、level、m、已知坑。**m 表必须写**，否则枚举零模型算不出来。
